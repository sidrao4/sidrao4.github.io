MIPS Processor Sep – Nov 2024
Description

Built a working MIPS processor from scratch in VHDL for a computer architecture course. Started with a single-cycle design covering the full datapath, control unit, and ALU, then extended it into hardware- and software-scheduled pipelines. The pipelined version ended up running instructions more than twice as fast as the original. Used Questa Sim throughout to simulate and verify each stage.

My Role

Did the full build myself — designed the datapath, wrote the VHDL for each component, wired up the control logic, and then added both pipeline versions on top. A lot of time went into debugging waveforms in simulation to track down timing issues.

Skills & Knowledge Gained
  • Writing and structuring VHDL for a real hardware design
  • How single-cycle and pipelined CPUs actually differ in practice
  • Dealing with hazards — stalls, forwarding, and why they matter
  • Getting comfortable reading waveforms and catching bugs in simulation
Resources Used
VHDL Questa Sim MIPS ISA
TuneFlow Aug – Nov 2024
Description

TuneFlow is an Android app where you can see what songs your friends are recommending and get personalized suggestions pulled from Spotify based on that. We integrated with the Spotify Web API to pull in user data and generate recommendations, and it ended up boosting daily active users by 40%. The app has several screens I designed and built to keep the experience simple and easy to navigate.

My Role

I was the frontend developer — built all the screens in Java, hooked up the Spotify API using Volley for the network calls, and handled how recommendations were displayed. I also wrote unit tests with JUnit and Mockito and used Postman to test the API endpoints while building out the integration.

Skills & Knowledge Gained
  • Building Android UIs in Java and working with XML layouts
  • Connecting to a real third-party API (Spotify) and navigating OAuth
  • Making async network requests with Volley
  • Writing unit tests and learning when mocking actually helps
  • Using Postman to debug API calls before wiring them into the app
Resources Used
Java Android SDK Spotify Web API Volley JUnit Mockito Postman XML
Bomb Defusal Robot Mar – Apr 2024
Description

For an embedded systems course, our team programmed a modified Roomba with a Tiva microcontroller attached to navigate a course and "defuse a bomb" in under 5 minutes. We wrote C directly against the hardware to read sensors and store data in real time, which brought the robot's response time down by about 30%. I also built a Python GUI that received live data from the robot over WiFi and plotted it as a graph so the driver could actually see what the sensors were picking up.

My Role

Worked on both sides of the project — the C firmware on the Tiva for reading sensors and managing memory, and the Python GUI on the laptop side that displayed live graphs of the incoming data. It was useful to see both ends of the system and how the data flowed between them.

Skills & Knowledge Gained
  • Writing C close to the metal — registers, interrupts, peripherals
  • Reading and storing sensor data reliably under time constraints
  • Getting two systems (robot and laptop) talking wirelessly
  • Building a live-updating GUI in Python with Matplotlib and NumPy
  • Working as a team under a real deadline with a physical result
Resources Used
C Tiva Microcontroller Python Matplotlib NumPy
